# 조리로봇 화재 인식 — 실사 합성 학습 PoC

급식실 튀김 조리 로봇용 화재 탐지 모델. **실제 화재 이미지 0장으로 학습.**
실주방 프레임 + 실화염 영상을 합성해 학습, 공개 실화재 데이터셋(D-Fire)으로 검증.

급식실에 실제로 불을 낼 수 없음 → 합성으로 학습. 자율주행 코너케이스와 같은 구조의 문제.

![합성 예시](docs/synthesis.jpg)

*위: 실제 급식실 프레임 / 아래: 화염 합성 결과. 초록 박스는 수작업이 아니라 합성 좌표에서 자동 생성된 YOLO 라벨.*

## 결과

| 라인 | 상태 | 핵심 근거 |
|---|---|---|
| **화염 탐지** | **검증 완료** | 급식실 오탐 88.0% → 1.3% · 판별비 0.69 → **17.5** (25배) |
| **웹3D 렌더 전이** | **성립** | 실사 픽셀 0장인 절차적 화염 **81.0%** 탐지 (IoU 0.5 기준 70.0%) |
| **탐지 좌표 신뢰도** | **사용 가능** | IoU 유지율 **86.4%** → 파이프라인 5단계 진입 가능 |
| **연기 조기 경보** | **미해결 · 종결** | 조리 연기/수증기 판별비 0.54 → 0.75, 1 미달 (단일 프레임 한계) |

**학습에 쓴 실제 화재 이미지 0장, 실제 연기 이미지 0장, 수작업 바운딩박스 0건.**
평가는 전부 실제 사진. 합성으로 학습해 합성으로 평가하면 아무것도 증명되지 않음.

## 입력과 출력

**입력** — 급식실 CCTV/촬영 프레임 1장 (1920×1080 또는 960×540, JPEG)

**출력** — 화재 바운딩박스 + 신뢰도

```json
[{"class": "fire", "conf": 0.41, "bbox": [612, 338, 799, 585]}]
```

**학습 데이터 생성**

```
실주방 프레임 (조리기구 위치·폭 수작업 지정)
    + 실화염 영상에서 추출한 알파 화염 390종
    ↓ 합성 + 아티팩트 무작위화
합성 화재 이미지 + YOLO 라벨 (자동 생성 · 수작업 라벨링 0건)
```

## 평가 설계

**평가에 합성 이미지를 쓰지 않음.** 전부 실제 사진이며, 실패 원인을 구분하기 위해 그룹을 나눔.
1~5회차는 A·B·C 3그룹, 6회차에서 smoke 클래스를 추가하며 A-smoke·D를 신설, 7회차 직전에 E를 신설.

| 그룹 | 구성 | 답하는 질문 | 학습 사용 |
|---|---|---|---|
| **A-fire** | D-Fire 실화재 150장 | 합성 학습이 실사에 전이되는가 | 미사용 |
| **A-smoke** | D-Fire 실연기 150장 | 연기도 같은 방식으로 전이되는가 | 미사용 |
| **B** | 급식실 CCTV 정상 조리 75장 | 배치 환경에서 오작동하지 않는가 | 미사용 |
| **C** | D-Fire 배경 75장 (화재 없음) | 화재를 배웠는가, 도메인을 외웠는가 | 미사용 |
| **D** | 수증기 352장 (스톡 24개 영상) | 김을 연기로 오인하는가 | 미사용 |
| **E** | 조리 연기 179장 (스톡 14개 영상) | 잡아야 할 조리 연기를 잡는가 | 미사용 |

읽는 법 — A↓ + C↓ 는 전이 실패, A↓ + C↑ 는 도메인 암기, B↑ 는 조리 중 오작동.
D와 E는 짝으로 읽어 **판별비 E/D** 를 냄. 1 미만이면 잡아야 할 것보다 무시할 것에 더 반응한다는 뜻.

**학습·평가는 영상 단위로 분리.** 연속 프레임은 배경이 거의 같아 프레임 단위 분리로는 누수 차단 불가.

| C 배경 오탐 | 1.3%* | 1.3% | 5.3% |
| A-smoke 연기 인식 | — | 22.0% | 12.0% |
| D 수증기 오탐 | — | 30.1% | 11.9% |
| E 조리 연기 인식 | — | 11.7% | 8.9% |

## 재현

`notebooks/gate.ipynb`를 Colab(GPU)에서 위에서부터 실행. 전체 약 1시간.
첫 셀에서 저장소 압축본 + `assets_1~4.zip` 업로드. D-Fire 다운로드에 Kaggle 계정 필요.

명령줄:

```bash
pip install ultralytics kagglehub

# 1. D-Fire 필터링 → 평가셋 A(150장)·C(75장) + 학습용 배경 목록
python scripts/dfire_eval_set.py --dfire /path/to/d-fire --out eval

# 2. 합성 학습셋 생성 (positive 1,510 / negative 836)
python scripts/synthesize.py --assets assets --out ds \
    --dfire-bg-list eval/train_bg.txt --dfire-bg-count 600 --haze-prob 0.5

# 3. 학습
yolo detect train model=yolov8s.pt data=ds/data.yaml epochs=60 imgsz=640 batch=16

# 4. 채점 (A/B/C + 기준선 곡선 + 판정)
python scripts/eval_gate.py --weights runs/detect/train/weights/best.pt \
    --eval-dir eval --cctv assets/eval_neg --conf 0.10
```

소요 — 데이터 생성 3분 / 학습 50분 / 채점 1분

**학습 없이 결과만 확인** — 3단계를 건너뛰고 4단계에서 `--weights assets/weights/round5_best.pt`

**회차 재현** — `--haze-prob 0` = 4회차 / `--dfire-bg-list`까지 제거 = 3회차

## 원칙

**평가에 합성 이미지 미사용** — A·B·C 전부 실제 사진. 합성으로 학습해 합성으로 평가하면 아무것도 증명되지 않음.

**학습·평가는 영상 단위 분리** — 개원중 CCTV는 학습에 단 한 프레임도 미사용. 연속 프레임은 배경이 거의 같아 프레임 단위 분리로는 누수 차단 불가.

**판정 기준을 결과보다 먼저 확정** — "recall ≥50% 확장 / 20~50% 보강 / <20% 중단, B >15% 시 recall 무관하게 보강"을 1회차 실행 전 코드에 명시, 이후 미수정.
웹3D 테스트도 동일 — 캡처 전 `web3d/PREREGISTER.md`에 통과선·해석 규칙·예상 결과를 확정하고 이후 미수정.

**불리한 수치도 함께 공개** — 웹3D는 절차적 85.0%만이 아니라 아틀라스 96.0%와 1차 92.5%를 나란히 기록. 두 조건 차이(11.0p)를 실사 텍스처가 기여한 몫으로 명시.

**한 회차에 한 변수만 변경** — 2회차에서 5가지를 동시에 바꿔 원인 특정에 실패한 뒤 도입. 3·4·5회차는 이 원칙으로 각각 하나의 결론 확보.

**합성 아티팩트는 제거가 아니라 무작위화** — 이미지마다 경계 강도·색온도·노이즈·압축률을 다르게 부여해 합성 흔적이 일관된 단서가 되지 못하게 함. 사실성을 높이는 것보다 이쪽이 전이에 유효.

**평가 A는 주방 화재가 아님**
D-Fire에 실내 근접 화재가 희소 → 필터링 후에도 산불·차량화재·야외 화재가 대부분.
따라서 A 42%는 "주방 화재를 42% 잡는다"가 아니라 **"도메인이 다른 일반 실화재를 42% 잡는다"**. 원래 의도보다 어려운 시험이지만 배치 환경 성능을 직접 말해주지 않음.

**A 42~44%는 현재 화염 소재의 천장**
3·4·5회차에서 동일하게 관측. 기준선을 0.03까지 낮춰도 상승 없음 — 미탐지분은 저신뢰가 아니라 무반응.
5회차에서 대기 산란으로 직접 시험했으나 천장 불변. 데이터셋 구성 조정으로는 돌파 불가, 소재 종류 변경 필요.

**B의 실효 표본 수 < 75**
고정 CCTV라 145프레임 중 시각적으로 구별되는 장면이 12개.
2.7% = 75장 중 2장. 회차 간 방향성(29.3%→6.7%)은 곡선 전 구간에서 일관되어 신뢰 가능하나, **절대값을 정밀 성능 수치로 인용 불가.**

**처음 보는 주방으로의 일반화 미검증**
개원중 1곳에서만 측정. 실제 배치에서는 현장 영상으로 보정하는 것이 표준 → "무보정 오탐률"과 "현장 보정 후 오탐률"을 분리 보고하는 것이 정확.

**정지 이미지 기준**
실시간 영상 동작 / 프레임 간 일관성 / 추론 지연 미측정.

**본 작업은 타당성 검증(PoC)일 뿐, 제품 검증이 아님.**

**웹3D 박스 위치는 렌더 화면에서만 검증됨**
IoU 측정 결과 조건 P 유지율 86.4%로 좌표 사용 가능 판정. 다만 이는 **렌더 화면 기준**이며,
실제 CCTV 영상에서 같은 유지율이 나온다는 근거는 아님. 탐지 81건 중 11건은 여전히 위치가 어긋남.

**웹3D는 렌더 화면이지 CCTV 화면이 아님**
압축 열화·모션 블러·저조도 노이즈·렌즈 왜곡이 없음. 실제 급식실 CCTV보다 쉬운 조건.
씬도 인덕션 튀김 냄비 1종으로, 급식실 조리 형태 전반을 대표하지 않음.

**수증기 평가군(D)은 급식실이 아님**
스톡 영상 24개, 김을 주인공으로 찍은 클로즈업이라 실제 급식실보다 어려운 조건.
D 수치(6회차 30.1% / 7회차 11.9%)를 급식실 오탐률로 그대로 인용 불가.
7회차에서 D가 내려가는 동안 급식실 CCTV 오탐(B)은 오히려 올랐으므로, 두 지표가 같은 것을
재고 있지 않음이 드러남 — D는 진한 김, B는 멀고 옅은 김.

**연기 조기 경보 — 미해결로 종결**
6·7회차 두 번의 통제 실험 모두 조리 연기/수증기 판별비 1 미달(0.54 → 0.75).
7회차는 판별비가 올랐으나 정탐(E 11.7→8.9%)이 함께 내려간 결과이며,
급식실 오탐은 2.7→13.3%로 오히려 악화. **오탐이 사라진 것이 아니라 자리를 옮김.**
합성 검증 mAP50 0.939 대 실사 조리 연기 8.9%의 격차가 문제의 성격을 보여줌.
정지 화면에서 김과 연기는 같은 물체이며 구별 단서는 시간 변화에 있을 가능성이 높음.
**다중 프레임 설계가 필요하며 본 PoC 범위 밖.** 화염 탐지와 같은 성숙도로 서술하지 않음.

**연기 소재는 출처 편중**
248종 중 상당수가 소수 영상에서 나옴. 다만 7회차 결과를 보면 소재 확대만으로
해결될 문제로 보이지 않음 — 소재를 조리 규모로 바꿨을 때 정탐이 오르지 않았음.

**급식실 8곳이 negative 다양성의 병목**
3회차에서 급식실 5곳→8곳(negative 70→236장)만 바꿔 주방 오탐 88%→28%. 단일 변수로 얻은 가장 큰 개선폭.
곡선이 평평해지지 않은 상태에서 자료가 떨어진 것이므로 **8곳이 포화점이라는 근거는 없음.**
20~30곳으로 확대 시 추가 개선 여지가 크다고 보나, 확인되지 않은 추정.

**화염 소재 11개도 같은 성격의 병목**
A 42~44% 천장이 3·4·5회차에서 불변. 소재 종류를 늘리거나 세그멘테이션으로 실화재 영상에서 화염 영역을 직접 추출하는 방향이 남은 선택지.

## 다음 단계

화염 탐지 라인은 검증이 끝남 — 판별비 17.5, 웹3D 절차적 화염 전이 성립, IoU 관문 통과.
다음은 이 탐지 결과를 실제 대응으로 잇는 구간.

**1. 탐지 JSON 규격화 (파이프라인 5단계)** — 박스 좌표·신뢰도에 더해 화구 식별, 카메라 ID, 시각을 포함. 단일 프레임 인식률이 42%이므로 N프레임 중 M회 탐지로 경보를 올리는 시간축 누적을 함께 설계. 연기에서 쓰지 못한 시간축을 화염에서는 쓸 수 있음.

**2. 행동 목록·안전 수칙 확보 (6·8단계의 전제)** — 로봇이 실제로 가능한 동작, 인덕션 원격 차단 가능 여부, 후드 연동 여부, 급식실 화재 시 규정된 조치 순서. **현장·사양서에서 확인이 필요한 항목이며 이것 없이는 6단계 이후를 지을 수 없음.**

**3. VLM 행동 선택 + 안전 규칙 (7·8단계)** — 상황과 정답 행동의 짝으로 정확도 측정. 정답 세트가 2번에서 나오므로 순서가 묶여 있음.

**4. 웹3D 로봇 차단 시연 (9단계)** — 씬과 좌표 신뢰도는 이미 확보됨.

**5. negative 확대 (급식실 20~30곳)** — 3회차 곡선이 포화 전에 끊긴 상태. 외부 협조 대기.

**6. 주방 화재 전용 평가셋** — 평가 A가 산불·차량화재 위주라 배치 환경 성능을 직접 말해주지 못함.

**7. 연기 조기 경보 재도전 (범위 밖)** — 다중 프레임 설계. 웹3D로 연속 프레임을 만들 수 있어 자료 수집 없이 착수 가능한 점이 이점.

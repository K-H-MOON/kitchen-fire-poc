# 탐지 JSON 규격 v1.0 — 파이프라인 5단계

작성 2026-08-06. 탐지기(4단계)의 출력을 뒤 단계가 쓸 수 있는 형태로 규격화함.

## 왜 필요한가

지금 모델의 출력은 `박스 [812,344,905,498], 신뢰도 0.62` 뿐임.
이것만으로는 7단계 VLM 이 아무 판단도 할 수 없음 — **어느 화구인지, 언제인지,
얼마나 큰지, 처음 뜬 경보인지 이어지는 경보인지**를 모르기 때문임.

이 규격은 그 공백을 메움. 좌표를 쓸 수 있다는 근거는 웹3D IoU 측정에서
유지율 86.4%로 확인했음([WEB3D.md](WEB3D.md)).

## 한 프레임의 출력

```json
{
  "schema": "kitchen-fire-detect/1.0",
  "camera_id": "gaewon-01",
  "ts": "2026-08-06T11:42:03.000Z",
  "frame_seq": 1043,
  "model": {
    "weights": "round10_best.pt",
    "imgsz": 640,
    "conf_th": 0.10
  },
  "detections": [
    {
      "class": "fire",
      "conf": 0.62,
      "bbox_xyxy": [812, 344, 905, 498],
      "bbox_norm": [0.634, 0.478, 0.707, 0.692],
      "area_ratio": 0.0213,
      "station_id": "fryer-1",
      "station_overlap": 0.87
    }
  ],
  "temporal": {
    "rule": "1-of-1",
    "window_n": 1,
    "hits_in_window": 1
  },
  "alarm": {
    "raised": true,
    "event_id": "gaewon-01-20260806T114203",
    "first_seen_ts": "2026-08-06T11:42:03.000Z",
    "duration_s": 0.0,
    "max_conf_in_event": 0.62,
    "max_area_ratio_in_event": 0.0213
  }
}
```

한 프레임당 한 줄. 파일로 저장할 때는 **JSON Lines**(`.jsonl`) 를 씀 —
스트림에 그대로 이어 붙일 수 있고, 중간이 깨져도 나머지를 읽을 수 있기 때문임.

## 필드 설명

### 최상위

| 필드 | 뜻 |
|---|---|
| `schema` | 규격 버전. 뒤 단계가 호환성을 판단할 수 있게 둠 |
| `camera_id` | 카메라 식별자. 급식실 한 곳에 여러 대가 붙을 수 있음 |
| `ts` | 프레임 촬영 시각 (ISO 8601, UTC) |
| `frame_seq` | 스트림 시작부터의 프레임 번호 |
| `model` | 어떤 가중치·설정으로 낸 결과인지. **회차가 바뀌면 수치가 달라지므로 반드시 남김** |

### `detections[]`

| 필드 | 뜻 |
|---|---|
| `class` | 현재는 `fire` 하나. 연기 라인은 미해결로 종결됨 |
| `conf` | 신뢰도 |
| `bbox_xyxy` | 픽셀 좌표 |
| `bbox_norm` | 0\~1 정규화 좌표. 해상도가 다른 카메라 간 비교용 |
| `area_ratio` | 박스 면적 ÷ 화면 면적. **조기 경보인지 이미 커진 불인지를 가름** |
| `station_id` | 박스 중심이 속한 화구. 어디에도 안 속하면 `null` |
| `station_overlap` | 박스와 화구 영역의 겹침 비율 |

`area_ratio` 를 넣는 이유 — 평가군 F 에서 이 값으로 구간을 나눠 측정했으며,
**2% 미만이 조기 경보 구간**임. 10회차 가중치의 해당 구간 인식률은 별도 기록에 있음.

`station_id` 가 `null` 인 경우를 버리지 않음. **화구 밖 화재도 화재이며 대응이 다름** —
화구 화재는 열원 차단이 통하지만 바닥 화재는 통하지 않음.

### `temporal`

시간축 M-of-N 측정 결과 **오탐 억제에는 쓸 수 없음**이 확인됐으므로
([PREREGISTER_TIME.md](PREREGISTER_TIME.md)), 기본값은 `1-of-1` 임.
다만 사건 단위 탐지는 8/8 로 성립했으므로 **필드는 남겨 둠** — 뒤 단계에서
"몇 프레임 연속으로 보였는가"를 참고 정보로 쓸 수 있기 때문임.

### `alarm`

같은 화재가 이어지는 동안 **하나의 사건으로 묶음.** 이것이 없으면 VLM 이
초당 한 번씩 같은 질문을 받게 됨.

| 필드 | 뜻 |
|---|---|
| `event_id` | 사건 식별자. 카메라 ID + 최초 시각 |
| `first_seen_ts` | 사건이 처음 감지된 시각 |
| `duration_s` | 사건 시작부터 현재 프레임까지 경과 초 |
| `max_conf_in_event` | 사건 중 최고 신뢰도 |
| `max_area_ratio_in_event` | 사건 중 최대 화염 크기. **불이 커지고 있는지 판단용** |

탐지가 끊겨도 **`gap_tolerance_s` (기본 10초) 안에 다시 잡히면 같은 사건**으로 봄.
시간축 측정에서 화재 구간에도 탐지가 드문드문 빠지는 것이 확인됐기 때문임
(evt7 12프레임 중 3장).

## 화구 영역 정의

카메라마다 `stations/<camera_id>.json` 에 둠.

```json
{
  "camera_id": "gaewon-01",
  "frame_size": [800, 450],
  "stations": [
    { "id": "fryer-1", "type": "fryer", "bbox_xyxy": [330, 5, 566, 150],
      "note": "식용유 튀김솥. 주 대응 대상" },
    { "id": "basket-area", "type": "staging", "bbox_xyxy": [150, 250, 530, 440],
      "note": "튀김 바구니·카트 구역. 화구는 아니나 화재 시 대응이 다름" }
  ],
  "excluded": [
    { "id": "pot-3", "reason": "미사용 화구. 기름 없음. 사용 시작하면 추가할 것" },
    { "id": "robot-arm", "reason": "8단계에서 로봇 정지 판단에 필요해지면 추가할 것" }
  ]
}
```

`excluded` 를 남기는 이유 — **뺀 것도 결정이므로 기록함.** 나중에 미사용 화구를
쓰기 시작하면 다시 넣어야 하는데, 기록이 없으면 왜 빠졌는지 알 수 없음.

## 한계

- **고정 카메라가 전제임.** 논현중 영상은 손으로 든 카메라라 프레임마다 조리기구
  위치가 달라 화구 영역을 정의할 수 없었음. `station_id` 를 붙이려면 카메라가
  고정돼 있어야 함.
- **화구 영역이 사각형임.** 실제 조리기구는 원형이고 카메라가 비스듬해 타원에 가까움.
  사각형은 주변을 과하게 포함함. 다각형으로 바꾸는 것이 정확하나 지금은 단순하게 둠.
- **`station_id` 로 오탐을 거르지 않음.** 논현중 오탐이 전부 조리사 소매이고
  이는 화구 영역 밖이므로, 뒤 단계에서 "화구 밖 탐지는 낮게 본다"는 규칙을 걸 수 있음.
  **다만 그것은 회피이지 해결이 아님** — 탐지기가 조리복을 화염으로 보는 문제는
  그대로 남으며, 화구 밖에서 실제로 난 불도 함께 약화됨.
- **시각(`ts`)이 실제 촬영 시각이 아님.** 지금은 프레임 번호와 fps 로 계산한 값임.
  실제 CCTV 연동 시 스트림의 타임스탬프로 바꿔야 함.
- **카메라가 한 대뿐임.** 여러 대가 같은 화재를 볼 때의 사건 병합은 다루지 않음.

예시 로그 두 개를 저장소에 넣어 둠 — 규격을 글로 설명하는 것보다 실제 출력이 명확함.

| 파일 | 내용 | 프레임 | 탐지 | 사건 |
|---|---|---|---|---|
| [`examples/log_normal.jsonl`](examples/log_normal.jsonl) | 개원중 CCTV 정상 조리 (고정 카메라, 화구 영역 적용) | 75 | 8 | 2 |
| [`examples/log_fire.jsonl`](examples/log_fire.jsonl) | 화재 사건 evt5 (다른 카메라, 화구 영역 없음) | 29 | 24 | 1 |

### 사건 요약 — 뒤 단계가 실제로 받는 단위

| | 최고 신뢰도 | 최대 크기 | 지속 | 화구 |
|---|---|---|---|---|
| 정상 조리 · 사건 1 | 0.251 | 0.041 | 16초 | basket-area / 화구 밖 |
| 정상 조리 · 사건 2 | 0.355 | 0.176 | 13초 | 화구 밖 |
| **화재 사건** | **0.903** | **0.223** | **28초** | (화구 영역 미정의) |

**사건 병합이 의도대로 동작함.** 화재 29프레임 중 5프레임에서 탐지가 빠졌으나
10초 공백 허용 규칙 덕분에 하나의 사건으로 유지됨. 정상 조리 쪽도 프레임 5·10·12·21의
드문드문한 탐지가 한 사건으로 묶임.

### 관찰 — 사건 단위 신뢰도가 갈림

이 카메라에서는 화재가 0.903, 오탐이 0.251·0.355 로 명확히 갈림.
`max_conf_in_event` 로 자르면 이 자료에서는 완전히 분리됨.

**그러나 일반화할 수 없음.** 시간축 사후 탐색에서 **논현중은 conf 0.70 에서도
시간당 49.7회 오탐**이 확인됐음. 개원중 오탐이 약한 것은 그 카메라의 특성이며,
처음 보는 급식실에서는 같은 규칙이 통하지 않음. **카메라 한 대의 결과임.**

### 관찰 — 화구 게이팅의 효과와 대가

탐지 8건의 위치는 **화구 밖 5건, basket-area 3건, `fryer-1` 안 0건** 임.
따라서 "튀김솥 영역 안의 탐지만 경보로 올린다"는 규칙을 걸면 **이 카메라의 오탐이
전부 사라짐.**

대가가 분명함. **화구 밖 화재를 통째로 놓침.** 바닥에 흘러 붙은 기름 화재나
바구니 구역 화재는 대응이 더 급할 수 있음. 이 규칙은 **회피이지 해결이 아님** —
탐지기가 조리복과 방진복을 화염으로 보는 문제는 그대로 남음.

### 남은 문제

- **시각이 실제 촬영 시각이 아님.** `2026-01-01T00:00:00Z` 부터 프레임 번호로 계산한 값임.
  `--start-ts` 로 기준 시각을 넣을 수 있으나 예시 로그는 기본값 그대로임.
- **정상 조리 오탐 박스가 큼.** 사건 2의 최대 크기가 0.176 으로 화면의 17.6% 임.
  왼쪽 가장자리의 흰 방진복 로봇 커버에 걸린 것이며, 크기로도 걸러지지 않음.

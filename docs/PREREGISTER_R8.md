# 8회차 사전 등록 — 입력 해상도 640 → 960

작성 2026-08-04, **학습 이전에 확정.** 이후 수정 금지.

## 왜 하는가

1\~7회차는 **학습 데이터 구성만** 바꿨다. 모델 크기·입력 해상도·추론 방식은 전 회차 고정.
손대지 않은 축이 통째로 남아 있으며, 그중 해상도가 가장 직접적인 근거를 가진다.

실화재 인식률 A가 3·4·5회차에서 42\~44%로 고정됐고, 기준선을 0.03까지 낮춰도 오르지 않았다.
미탐분이 저신뢰가 아니라 **무반응**이라는 뜻이다. 미탐 사례를 보면 멀고 작은 화염이 다수이며,
작은 물체는 입력 해상도의 직접적인 영향을 받는다. 640픽셀에서 화면의 2%를 차지하는 화염은
약 90픽셀이나 960에서는 135픽셀이 된다.

## 이번 회차가 바꾸는 것

**변수 하나: `imgsz` 640 → 960.**

- 학습 데이터 구성은 **5회차와 완전히 동일** (`scripts/synthesize.py`, `--haze-prob 0.5`,
  D-Fire 배경 600쌍, fire 단일 클래스)
- 모델 `yolov8s.pt`, 에폭 60, **배치 16 유지**
- 평가셋 A·B·C 동일

배치를 함께 낮추면 변수가 둘이 되므로 16을 유지한다. 7회차 로그 기준 640·배치16에서
GPU 메모리 4.62G였고, 화소 수 비례로 960에서 약 10.4G가 예상되므로 T4(14.9G)에 들어간다.
OOM 발생 시에만 8로 낮추고, 그 경우 배치 변경을 한계로 명시한다.

6·7회차의 smoke 클래스는 **쓰지 않는다.** 연기 라인은 미해결로 종결됐고, 배치 후보
가중치는 5회차(fire 단일 클래스)이므로 그 위에서 비교하는 것이 맞다.

## 판정 기준

운용 임계값 **conf 0.10**. 5회차 가중치를 같은 노트북에서 함께 채점해 나란히 비교한다.

| 지표 | 기준 |
|---|---|
| **A 실화재 인식률** | **+5%p 이상 상승 → 채택** / +2\~5%p 부분 / +2%p 미만 기각 |
| B 급식실 오탐률 | 5회차 대비 +3%p 이내 유지. 초과 시 A와 무관하게 기각 |
| C 배경 오탐률 | 참고 기록 |
| 프레임당 추론 시간 | 참고 기록. 실시간 제약 판단용 |

주 지표를 A로 두는 이유 — 이번 변경의 가설이 "작은 화염을 놓치는 것이 해상도 탓"이므로,
검증 대상은 인식률이다. 다만 오탐이 함께 오르면 의미가 없으므로 B를 기각 조건에 둔다.

## 미리 밝혀 두는 예상과 해석 규칙

- **A가 오르지 않으면 42\~44% 천장이 해상도 문제가 아니라는 근거가 된다.** 그 경우 남은
  후보는 화염 소재 다양성이며, 3·4·5회차의 진단과 일치한다. 실패도 정보다.
- 960 학습은 추론도 느려진다. A가 올라도 실시간 제약을 못 맞추면 배치용으로 채택 불가.
  따라서 추론 시간을 함께 기록한다.
- A는 D-Fire 기준이며 산불·차량화재가 다수다. **A 상승이 급식실 화재 성능 향상을 뜻하지 않는다.**
- 결과가 어떻든 A·B·C와 추론 시간을 모두 공개한다. 5회차 수치를 기준선으로 병기한다.

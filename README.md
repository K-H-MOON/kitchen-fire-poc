# 조리로봇 화재 인식 — 실사 합성 학습 PoC

> **종결된 기록.** 2026-08-06, 프로젝트 주제 변경으로 실험을 종료함.
> 학습 10회차 + 시간축 측정 + 파이프라인 5단계까지 진행했고, 이후 계획은 착수하지 않음.
> 아래 내용은 **그 시점까지의 결과와 한계를 그대로 남긴 것**임.

급식실 튀김 조리 로봇용 화재 탐지 모델. **실제 화재 이미지 0장으로 학습.**
실주방 프레임 + 실화염 영상을 합성해 학습, 공개 실화재 데이터셋(D-Fire)으로 검증.

급식실에 실제로 불을 낼 수 없음 → 합성으로 학습. 자율주행 코너케이스와 같은 구조의 문제.

![합성 예시](docs/synthesis.jpg)

| 라인 | 상태 | 핵심 근거 |
|---|---|---|
| **화염 탐지 (학습한 급식실)** | **검증 완료** | 급식실 오탐 88.0% → 1.3% · 판별비 0.69 → **17.5** (25배) |
| **주방 화재 인식** | **개선 확인 · 미배치** | F 인식률 42.3% → **49.7%**, 판별비 F 5.97 → **25.33** (10회차 채택) |
| **학습하지 않은 급식실** | **개선 확인 · 미배치** | 오탐 63.3% → **31.2%** · 판별비 F/논현중 0.67 → **1.59** (처음으로 1 돌파) |
| **웹3D 렌더 전이** | **성립** | 실사 픽셀 0장인 절차적 화염 **81.0%** 탐지 (IoU 0.5 기준 70.0%) |
| **탐지 좌표 신뢰도** | **사용 가능** | IoU 유지율 **86.4%** → 파이프라인 5단계 진입 가능 |
| **사건 단위 탐지** | **성립** | 화재 8사건 **8/8 탐지 · 지연 0초** (프레임 49.7% → 사건 100%) |
| **시간축 오탐 억제** | **미해결 · 종결** | 임계값 x 규칙 49개 조합 전부 실패. 최선이 시간당 74.5회 |
| **연기 조기 경보** | **미해결 · 종결** | 조리 연기/수증기 판별비 0.54 → 0.75, 1 미달 (단일 프레임 한계) |
| **탐지 JSON (5단계)** | **규격 확정 · 동작 확인** | 화구 식별·사건 병합·크기 기록. [예시 로그](docs/examples/) 공개 |

*오탐 = 정상 조리를 화재로 잘못 알리는 것(false positive) · 정탐 = 실제 화재를 제대로 잡는 것 ·
판별비 = 정탐률 ÷ 오탐률(A/B 또는 E/D). 둘 중 하나만 좋아져서는 오르지 않음.*

**학습에 쓴 실제 화재 이미지 0장, 실제 연기 이미지 0장, 수작업 바운딩박스 0건.**
평가는 전부 실제 사진. 합성으로 학습해 합성으로 평가하면 아무것도 증명되지 않음.

### 회차별 한 줄 요약

| 회차 | 변경사항 | 결과 |
|---|---|---|
| 1 | positive 910 / negative 70 | 전이 확인(A 60.7%), 그러나 주방 오탐 88.0% |
| 2 | negative에 주황 물체 크롭 투입 | **실패** — A 12.7% 붕괴. 5가지를 동시에 변경해 원인 특정 불가 |
| 3 | negative만 70→236장 (급식실 5→8곳) | B 88%→28%. **negative 다양성이 오탐을 지배** |
| 4 | + 주방 밖 배경 600쌍 | B 28%→9.3%. 배경 다양성이 A를 올린다는 가설은 기각 |
| **5** | **+ positive 50%에 대기 산란** | **B 1.3% · 판별비 17.5** — 운용 가중치 확정 |
| 6 | + smoke 클래스 (연기 소재 197종) | 화염 회귀 없음. 연기/수증기 판별비 **0.54** |
| 7 | 연기를 조리 규모로 재조정 (소재 248종) | **실패** — 판별비 0.75이나 정탐도 하락, 급식실 오탐 5배 |
| 8 | 입력 해상도 640 → 960 | **기각** — A 34.7%로 올랐으나 급식실 오탐 2.7%→72.0% |
| **9** | **화염 소재 교체 (백열 코어 보존 + 724종)** | **기각 · 그러나 최대 수확** — F 42.3%→**56.8%**, 판별비 F 5.97→**28.98**. 급식실 오탐 69.3%로 기각 |
| **10** | **급식실 negative 확대 (9곳 236장 → 11곳 502장)** | **채택** — 학습하지 않은 급식실 오탐 91.7%→**31.2%**, 판별비 F/미사용 0.62→**1.59**. 운용 가중치 교체 |

*회차마다 변수를 하나씩만 변경. 2회차에서 다섯 가지를 동시에 변경해 원인 특정에 실패한 뒤 도입한 원칙.
1\~7회차는 학습 데이터 구성만 변경하고 모델·에폭·입력 크기를 고정(YOLOv8s / 60 epoch / 640px / T4).
8회차에서 처음으로 해상도를 변경.*

8회차 이후 **주방 화재 전용 평가군 F**를 신설함. 회차가 아니라 평가 설계의 변경임.

9회차는 기각됐으나 **주방 화염 인식이 처음으로 실질 상승**했고 원인이 규명됨 —
1\~8회차 소재는 알파 추출 과정에서 화염 중심의 백열부가 지워져 있었음(코어 알파 0.25).
그 결함을 고치자 F 인식률이 14.6%p 올랐으나, 같은 변경이 급식실의 밝고 무채색인
물체를 화염으로 만듦. **다만 이 진단은 10회차에서 기각됨** — 밝은 스테인리스가 화면 절반인
급식실에서 9회차 오탐이 0.0%였음. 진짜 원인은 노란 조리복이었고, 처방은 소재를 되돌리는 것이
아니라 급식실 negative를 늘리는 것이었음.

10회차에서 급식실을 9곳 236장에서 11곳 502장으로 늘리자 학습하지 않은 급식실 오탐이
91.7%에서 31.2%로 내려가며 **채택**됨. 운용 가중치를 5회차에서 10회차로 교체함.

## 입력과 출력

**입력** — 급식실 CCTV/촬영 프레임 1장 (1920×1080 또는 960×540, JPEG)

**출력** — 화재 바운딩박스 + 신뢰도

```json
[{"class": "fire", "conf": 0.41, "bbox": [612, 338, 799, 585]}]
```

**학습 데이터 생성**

```
실주방 프레임 (조리기구 위치·폭 수작업 지정)
    + 실화염 영상에서 추출한 알파 화염 390종
    ↓ 합성 + 아티팩트 무작위화
합성 화재 이미지 + YOLO 라벨 (자동 생성 · 수작업 라벨링 0건)
```

## 평가 설계

**평가에 합성 이미지를 쓰지 않음.** 전부 실제 사진이며, 실패 원인을 구분하기 위해 그룹을 나눔.
1\~5회차는 A·B·C 3그룹, 6회차에서 smoke 클래스를 추가하며 A-smoke·D를 신설, 7회차 직전에 E를 신설.

| 그룹 | 구성 | 답하는 질문 | 학습 사용 |
|---|---|---|---|
| **A-fire** | D-Fire 실화재 150장 | 합성 학습이 실사에 전이되는가 | 미사용 |
| **A-smoke** | D-Fire 실연기 150장 | 연기도 같은 방식으로 전이되는가 | 미사용 |
| **B** | 급식실 CCTV 정상 조리 75장 | 배치 환경에서 오작동하지 않는가 | 미사용 |
| **C** | D-Fire 배경 75장 (화재 없음) | 화재를 배웠는가, 도메인을 외웠는가 | 미사용 |
| **D** | 수증기 352장 (스톡 24개 영상) | 김을 연기로 오인하는가 | 미사용 |
| **E** | 조리 연기 179장 (스톡 14개 영상) | 잡아야 할 조리 연기를 잡는가 | 미사용 |
| **F** | 주방 화재 264장 / 화염없음 91장 (소방 재현 실험 7개) | **급식실과 같은 규모의 화염을 잡는가** | 미사용 |
| **논현중** | 급식실 정상 조리 109장 (10회차 신설) | **학습에서 본 적 없는 급식실에서 오작동하지 않는가** | 미사용 |
| **시퀀스** | 화재 8사건 113장 · 정상 664장 (연속 프레임, 1fps) | **사건 단위로는 얼마나 잡고 얼마나 헛울리는가** | 미사용 |

→ 상세: **[탐지 JSON 규격](docs/DETECT_SCHEMA.md)** · **[예시 로그](docs/examples/)**

읽는 법 — A↓ + C↓ 는 전이 실패, A↓ + C↑ 는 도메인 암기, B↑ 는 조리 중 오작동.
D와 E는 짝으로 읽어 **판별비 E/D** 를 냄. 1 미만이면 잡아야 할 것보다 무시할 것에 더 반응한다는 뜻.

**F는 A를 대체하기 위해 만든 평가군.** A(D-Fire)는 산불·차량화재가 다수라 조리기구 위 화염을
측정하지 못함. 8회차에서 A가 올랐는데 급식실 오탐이 27배로 폭증하며 그 한계가 확정됨.
F는 소방 기관의 화재 재현 실험 영상에서 뽑은 조리기구 위 식용유 화염이며, **같은 배경에서
불만 없는 장면 91장을 짝으로 둠** — 모델이 배경에 반응하는지 화염에 반응하는지 직접 갈라냄.

F의 주 지표는 **출처별 인식률의 macro 평균**. 한 영상이 264장 중 127장을 차지하나
연속 구간에서 나온 것이라 독립 관측이 아니므로, 장수 합산이 아니라 출처별 평균을 씀.

**학습·평가는 영상 단위로 분리.** 연속 프레임은 배경이 거의 같아 프레임 단위 분리로는 누수 차단 불가.

*6·7회차는 fire·smoke 2클래스, 5·8회차는 fire 단일 클래스*

*F는 9회차부터 주 지표. macro 오탐률은 화염없음 10장 이상인 출처만 포함(5회차 수치도 같은 기준으로 재계산)*

**운용 권장 가중치를 5회차에서 10회차로 교체함.** 5회차 이후 처음임.
10회차는 5회차 대비 F 인식률·F 오탐·판별비 F·논현중 오탐이 모두 개선됐고, 악화된 것은
개원중 오탐(2.7%→10.7%) 하나임. 개원중은 고정 CCTV로 실효 장면이 12개뿐이며,
논현중이 더 어렵고 정직한 시험임.

**판별비 F ÷ 논현중이 처음으로 1을 넘음(0.67 → 1.59).** 5회차와 9회차는 학습하지 않은 급식실의
정상 조리에 반응하는 빈도가 실제 주방 화재에 반응하는 빈도보다 높았음 — 경보기로 성립하지
않는 상태였음. 10회차에서 처음 뒤집힘. 연기 라인을 종결할 때 쓴 것과 같은 기준임.

### 시간축 M-of-N (10회차 가중치)

사진 한 장 기준 수치를 **사건 단위**로 바꿔 측정함. 사전 등록은
[PREREGISTER_TIME.md](docs/PREREGISTER_TIME.md).

| 지표 | 값 |
|---|---|
| **화재 사건 탐지** | **8/8** (지연 중앙 0초) |
| 학습한 급식실 허위 경보 | **0건** (217프레임) |
| **학습하지 않은 급식실 허위 경보** | **시간당 107.6회** |

**화재를 놓치는 문제는 사실상 해소됨.** 프레임 49.7%가 사건 단위로는 100%임.
화재가 여러 초 이어지기 때문임.

**그러나 오탐은 시간축으로 풀리지 않음.** 규칙을 가장 조여도(7-of-10) 시간당 57.9회이며
그 대가로 사건 탐지가 4/8로 반토막 남. 사후 탐색으로 임계값 7개 x 규칙 7개 = 49개 조합을
훑었으나 전부 실패함 — 사건 탐지 7/8 을 지키는 최저가 시간당 74.5회임.

원인은 두 가지임. 학습하지 않은 급식실의 오탐이 **짧지만(중앙 1초) 너무 잦고**(7분에 76번,
평균 5.7초에 한 번) 어떤 창으로도 빠져나가지 못함. 그리고 **conf 0.70 에서도 시간당
49.7회**여서 임계값으로도 걸러지지 않음 — 모델이 조리복 소매를 확신하고 있음.

**조기 경보의 상한도 드러남.** 점화 직후 구간의 최고 신뢰도가 **0.27**임(큰 불은 0.88~0.94).
임계값을 그 위로 올리는 순간 조기 경보를 포기하게 되며, **조기 경보와 오탐 억제가 같은
신뢰도 구간에서 겹쳐 있음.**

시간축 라인은 여기서 종결함. **남은 경로는 단일 프레임 오탐 자체를 줄이는 것 하나임.**

| **F 오탐률 (macro)** | **10.9%** |
| **판별비 F** | **3.86** |
| micro 인식률 | 40.9% (108/264) |
| micro 오탐률 | 11.0% (10/91) |

화염 면적비 구간별로 보면 2% 미만 28.6%, 2\~5% 40.9%, 5\~15% 39.7%, 15% 이상 49.5%임.
**크기 문제가 아님** — 가장 큰 구간조차 절반을 못 넘고, 놓친 사진 다수가 화면 절반을
채우는 불기둥임. 공통점은 크기가 아니라 **하얗게 날아간 색과 밝은 배경**이며,
학습 소재가 어두운 배경 위의 주황색 화염뿐인 것이 원인으로 보임 → 9회차 변수.

오탐 10장은 황동 냄비 4장, 수증기 2장, 어두운 물체 1장, 기타 3장임.
급식실은 스테인리스 조리기구와 김이 상시로 있으므로 앞의 둘은 반드시 다뤄야 함 → 10회차.

**A와 F를 같은 축에 놓고 비교하지 않음.** 대상이 다름.

## 재현

`notebooks/gate.ipynb`를 Colab(GPU)에서 위에서부터 실행. 전체 약 1시간.
첫 셀에서 저장소 압축본 + `assets_1\~4.zip` 업로드. D-Fire 다운로드에 Kaggle 계정 필요.

명령줄:

```bash
pip install ultralytics kagglehub

# 1. D-Fire 필터링 → 평가셋 A(150장)·C(75장) + 학습용 배경 목록
python scripts/dfire_eval_set.py --dfire /path/to/d-fire --out eval

# 2. 합성 학습셋 생성 (positive 1,510 / negative 836)
python scripts/synthesize.py --assets assets --out ds \
    --dfire-bg-list eval/train_bg.txt --dfire-bg-count 600 --haze-prob 0.5

# 3. 학습
yolo detect train model=yolov8s.pt data=ds/data.yaml epochs=60 imgsz=640 batch=16

# 4. 채점 (A/B/C + 기준선 곡선 + 판정)
python scripts/eval_gate.py --weights runs/detect/train/weights/best.pt \
    --eval-dir eval --cctv assets/eval_neg --conf 0.10
```

소요 — 데이터 생성 3분 / 학습 50분 / 채점 1분

**학습 없이 결과만 확인** — 3단계를 건너뛰고 4단계에서 `--weights assets/weights/round5_best.pt`

**회차 재현** — `--haze-prob 0` = 4회차 / `--dfire-bg-list`까지 제거 = 3회차

## 원칙

**평가에 합성 이미지 미사용** — A·B·C 전부 실제 사진. 합성으로 학습해 합성으로 평가하면 아무것도 증명되지 않음.

**학습·평가는 영상 단위 분리** — 개원중 CCTV는 학습에 단 한 프레임도 미사용. 연속 프레임은 배경이 거의 같아 프레임 단위 분리로는 누수 차단 불가.

**판정 기준을 결과보다 먼저 확정** — "recall ≥50% 확장 / 20\~50% 보강 / <20% 중단, B >15% 시 recall 무관하게 보강"을 1회차 실행 전 코드에 명시, 이후 미수정.
웹3D 테스트도 동일 — 캡처 전 `web3d/PREREGISTER.md`에 통과선·해석 규칙·예상 결과를 확정하고 이후 미수정.

**불리한 수치도 함께 공개** — 웹3D는 절차적 85.0%만이 아니라 아틀라스 96.0%와 1차 92.5%를 나란히 기록. 두 조건 차이(11.0p)를 실사 텍스처가 기여한 몫으로 명시.

**한 회차에 한 변수만 변경** — 2회차에서 5가지를 동시에 바꿔 원인 특정에 실패한 뒤 도입. 3·4·5회차는 이 원칙으로 각각 하나의 결론 확보.

**합성 아티팩트는 제거가 아니라 무작위화** — 이미지마다 경계 강도·색온도·노이즈·압축률을 다르게 부여해 합성 흔적이 일관된 단서가 되지 못하게 함. 사실성을 높이는 것보다 이쪽이 전이에 유효.

## 한계

**오탐은 시간축으로 풀리지 않음 — 종결**
"최근 N장 중 M장" 누적 판정과 신뢰도 임계값을 조합해 49개를 훑었으나 전부 실패함.
학습하지 않은 급식실의 허위 경보가 최선의 조합에서도 **시간당 74.5회**임(목표 6회).
오탐이 짧지만(중앙 1초) 5.7초에 한 번씩 나서 창을 빠져나가지 못하고,
**conf 0.70 에서도 시간당 49.7회**라 임계값으로도 걸러지지 않음.

**조기 경보와 오탐 억제가 같은 신뢰도 구간에서 겹침**
점화 직후 화염의 최고 신뢰도가 **0.27** 임. 큰 불은 0.88~0.94 로 여유가 있으나,
조기 경보가 잡아야 할 구간은 조리복 오탐과 같은 신뢰도 대역에 있음.
**임계값을 올려 오탐을 줄이는 방법은 조기 경보를 포기할 때만 가능함.**

**학습하지 않은 급식실에서는 여전히 오탐 31.2%**
10회차에서 91.7%에서 31.2%로 내렸으나 **정상 조리 열 장 중 세 장에서 경보가 울림.**
배치 수준이 아님. 남은 오탐 34장은 전부 노란 조리복 소매이며, 팔이 냄비 위로 뻗어
세로로 길쭉해진 순간에 몰려 있음. 색은 상당히 학습됐고 **형태가 남은 문제**임.

**오탐의 정체는 조리복이 아니라 "천" 전반임**
논현중(학습 미사용)의 오탐은 **노란 조리복 소매**이고, 개원중(학습 미사용)의 오탐은
5단계 로그에서 확인한 결과 **로봇을 덮은 흰 방진복**임. 색은 정반대이나 둘 다
**주름진 밝은 천**이며 세로로 길쭉한 형태임. 화염의 형태적 특징과 겹침.
착수하지 않은 11회차의 대상은 "조리복"이 아니라 **천 전반**이어야 했음.

**학습한 급식실 수치를 성능으로 읽으면 안 됨**
10회차의 영동중·원촌중 오탐은 0.0%이나 두 곳 모두 학습에 쓴 곳임. 낮게 나오는 것이 당연하며
성능의 근거가 되지 못함. **성능 판단은 학습에 쓰지 않은 논현중·개원중으로만 함.**

**두 미사용 급식실이 반대로 움직임**
10회차에서 논현중은 63.3%→31.2%로 좋아졌으나 개원중은 2.7%→10.7%로 나빠짐.

negative를 늘리면 모델이 조용해지는 방향으로 움직임. 기각 기준(−8%p)을 0.8%p 차이로 통과했음.

**평가 이미지 해상도가 오탐률을 크게 바꿈**
논현중을 가로 960으로 줄여 채점했을 때 5회차 45.9% / 9회차 83.5%였으나,

주방 화재 전용 평가군을 만들었으나 자료는 소방 기관의 시연·실험 영상임. 카메라가 고정돼 있고

일곱 곳 중 네 곳이 야외이고, 해상도도 400×224에서 1750×880까지 벌어져 있음.

거짓이 될 뻔했음.** 8회차에서도 미탐 사진을 보고 판정이 뒤집혔음 — 수치만으로 판단하지 않음.

**평가 A는 주방 화재가 아님 — 이 프로젝트 최대의 측정 한계**

8회차에서 이 한계가 구체적으로 드러남. 5회차가 놓치고 8회차가 새로 잡은 30장이

A가 7.4%p 올랐으나 그 상승이 우리 목적과 무관한 곳에서 왔음.

주방 화재 공개 데이터가 희소한 이유는 학습 데이터가 없는 이유와 같음 — 발생 순간이
촬영되는 경우가 드물고, CCTV에 잡혀도 사고 기록이라 공개되지 않음.
**급식실에 불을 낼 수 없어 합성으로 학습한 제약이 평가에도 그대로 걸려 있음.**
그래서 판정은 A가 아니라 B(실제 급식실 CCTV)를 신뢰 신호로 삼아 내림.

5회차 42.3%, 9회차 56.8%, 10회차 49.7%. **배치 후보(10회차)는 절반을 넘지 못함.** 조기 경보의 핵심인 면적비 2% 미만

여지가 있으나, 오탐도 함께 누적되므로 별도 측정이 필요함. 미실시.

3·4·5회차에서 동일하게 관측. 기준선을 0.03까지 낮춰도 상승 없음 — 미탐지분은 저신뢰가 아니라 무반응.

**학습하지 않은 주방으로의 일반화 미검증**
개원중 1곳에서만 측정. 실제 배치에서는 현장 영상으로 보정하는 것이 표준 → "무보정 오탐률"과 "현장 보정 후 오탐률"을 분리 보고하는 것이 정확.

**정지 이미지 기준**
실시간 영상 동작 / 프레임 간 일관성 / 추론 지연 미측정.

## 어디서 멈췄는가

**2026-08-06, 프로젝트 주제 변경으로 종료함.** 모델 성능이 목표에 미달해서가 아니라
팀 논의로 방향이 바뀌었기 때문임. 아래는 종료 시점의 상태와, 이어서 하려던 것들임.

### 종료 시점의 상태

**화염 탐지는 학습한 급식실에서 검증을 마침** — 오탐 88.0% → 1.3%, 판별비 17.5.

**주방 화재 인식은 처음 측정하고 개선까지 확인함** — 평가군 F 를 만들어 42.3% 에서
49.7% 로 올렸고, 학습하지 않은 급식실의 오탐을 63.3% 에서 31.2% 로 내림.
**판별비 F÷논현중이 0.67 에서 1.59 로, 처음으로 1을 넘김.**

**사건 단위 탐지는 성립함** — 화재 8사건 8/8, 지연 0초.

**배치 수준에는 이르지 못함** — 학습하지 않은 급식실에서 정상 조리 열 장 중 세 장에
경보가 울림. 시간축과 임계값으로 49개 조합을 훑었으나 어느 것도 이를 해결하지 못함.

**파이프라인은 5단계까지 지음** — 탐지 JSON 규격을 확정하고 예시 로그를 냄.
6단계 이후는 로봇 동작 목록과 급식실 화재 대응 규정이 필요해 착수하지 못함.

### 이어서 하려던 것 (미착수)

**1. 천 negative (11회차)** — 남은 오탐의 정체가 조리복과 방진복, 즉 **주름진 밝은 천**임이
5단계 로그에서 확인됨. 색은 정반대인데 형태가 같음. 이것이 유일하게 남은 경로였음.
밝은 색 조리복이 담긴 급식실 영상 확보가 전제.

**2. 학습 미사용 급식실 확대** — 학습에 쓰지 않은 급식실이 논현중·개원중 둘뿐이며
10회차에서 서로 반대 방향으로 움직임. 어느 쪽이 대표적인지 판단할 근거가 없음.

**3. 행동 목록·안전 수칙 확보** — 로봇이 실제로 가능한 동작, 인덕션 원격 차단 가능 여부,
급식실 화재 시 규정된 조치 순서. **현장·사양서 확인이 필요하며 이것 없이는
6단계 이후를 지을 수 없음.** 파이프라인이 5단계에서 멈춘 직접적 이유임.

**4. 합성 화염 배치 위치 현실성** — D-Fire 배경에 화염을 무작위로 놓아 하늘 한복판에
불이 생기는 경우가 있음. 효과는 측정된 바 없음.

**5. 실제 급식실 화재 자료 확보 (장기)** — F 는 소방 재현 실험이며 사고가 아님.
이 편향은 표본을 늘려 해결되지 않음.

**6. 연기 조기 경보 재도전 (범위 밖)** — 6·7회차에서 미해결로 종결함. 다중 프레임 설계 필요.

**급식실에 불을 낼 수 없다는 제약을 합성으로 우회할 수 있는가** — 부분적으로 가능함이

학습한 모델이 실제 주방 화재를 49.7% 인식함.

**측정 대상이 틀리면 아홉 회차를 헛돌 수 있다** — 8회차까지 평가군 A(D-Fire)로 판단했으나
그 안에 주방 화재가 거의 없었음. 평가군 F 를 만들고 나서야 무엇을 고쳐야 하는지 보였음.

**수치만으로 판단하면 세 번 속았을 것** — 평가군 F 첫 채점의 로고 오염(96.4% → 21.4%),
8회차의 산불 미탐 사진, 9회차의 잘못된 진단. 세 번 모두 **사진을 눈으로 본 것**이
결론을 바꿨음.

**사전 등록이 두 번 실제로 작동함** — 9회차는 F 판별비가 4.9배가 됐으나 미리 걸어둔
급식실 오탐 조건에 걸려 기각됨. 그 조건이 없었다면 정상 조리 화면의 69%에서 경보를
울리는 모델을 채택했을 것임.

**틀린 진단과 설계 실수도 지우지 않고 남김** — 9회차 진단 기각, macro 오탐률 설계 결함,
시간축 해석 규칙의 이분법 오류, 평가 해상도 17%p 차이. 전부 기록에 있음.
